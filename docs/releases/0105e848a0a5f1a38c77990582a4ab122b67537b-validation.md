- AI #26: post_ingest 품질 평가 질문이 markdown 장식 때문에 전부 탈락해 run이 실패하던 문제. 장식 제거 후 대조하고, 0건이면 실패 대신 `quality_skipped`로 마친다.
- AI #27: converter S3 Range GET 실패 원인(HTTP 상태·S3 오류 코드)을 기록하고 5xx·연결 오류만 1회 재시도.
- Platform #32(이 릴리스의 Deploy에서 처음 적용): configmap `SPEECH_LIVE_ENDPOINT`·`SPEECH_TRANSCRIPTION_ENDPOINT`·`MEETING_NOTES_ENDPOINT`, ALB idle timeout 120초. Platform #34: 로컬·kind용 MinIO 이미지 교체(운영 영향 없음).

## DB 변경과 호환성 (`expand-only`)

운영 마지막 배포(`8f7d60b8…`)는 Document V53, AI 스키마 `be6cbeb` 시점이다. 이번 배포는 Document만 바뀐다.

- V54: `meetings`·`meeting_streams`·`meeting_segments` 신규 테이블.
- V55: `meeting_notes` 신규 테이블.
- V56: `meetings`에 `recording_key`·`recording_content_type`·`recording_bytes`·`error`·`claimed_at` 컬럼과 `status='transcribing'` 부분 인덱스. `meetings`는 같은 릴리스의 V54가 만든 빈 테이블이라 잠금 영향 없음.
- 기존 테이블 변경·데이터 변경 없음. AI `pipeline/db`는 `be6cbeb` 이후 변경 없음.

**배포 전 필수:** 없음. V51 사전 조회 같은 데이터 충돌 조건이 없다. 배포 전 백업 시점 확보는 통상 절차대로.

**되돌림:** 이미지 롤백 시 V54~V56 테이블은 남지만 이전 앱은 참조하지 않는다(각 마이그레이션 PR에서 격리 DB로 이전 앱 롤백 확인: Document [PR #17](https://github.com/FruitionKR/Fruition-document/pull/17) `docs/db/v54-meetings-2026-09-28.md`, [PR #20](https://github.com/FruitionKR/Fruition-document/pull/20) `docs/db/v55-meeting-notes-2026-09-28.md`, [PR #21](https://github.com/FruitionKR/Fruition-document/pull/21) `docs/db/v56-meeting-recordings-2026-09-28.md`).

## 배포 후 확인

- `document-svc` 로그에 `[pipeline run 조회 실패] … runId=convert:` 경고가 더 이상 없는지.
- 회의 생성 → 실시간 받아쓰기 연결(`wss://api.<domain>/api/meetings/{id}/live`)이 ALB를 통과하고 60초 이상 유지되는지. 실패하면 ALB idle timeout·WAF 규칙 확인.
- 채팅 음성 입력·회의록 초안이 503 없이 응답하는지(configmap 키 3개 적용 확인: `kubectl -n fruition get cm fruition-config -o yaml | grep -E 'SPEECH_|MEETING_NOTES'`).
- PDF 위키 편입 실패 시 문서 오류 문구에 `status=422 detail=…`가 붙는지, converter 로그에 `convert-source-batch rejected` 경고가 남는지.
- 위키 편입 후 `[S3 PUT 연결 오류, 1회 재시도]` 경고 빈도. 잦으면 유휴 시간(30초) 재조정.
