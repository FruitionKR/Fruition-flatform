## 교체 구간

교체 순서는 converter → access-svc·document-svc·pipeline-api → 나머지 worker·frontend다.

- 새 document가 옛 maintenance worker보다 먼저 뜬다. 그 사이 회의록 command에 `response_language`가 실려 옛 worker가 거부할 수 있다. 회의록 생성은 몇 분 동안 실패할 수 있고, 운영 회의 데이터는 지금까지 0건이다.
- 옛 access pod가 남아 있는 동안 옛 필드 `auto_ingest_on_upload`만 바꾸면 PDF 변환 설정이 따라가지 않는다. 배포 뒤 issue 171의 조회로 두 값이 다른 워크스페이스를 확인한다.
- access V33·V34에는 `lock_timeout`이 없다. V33은 `workspaces` 전체 행을 UPDATE한다. 운영 행 수가 적어 짧게 끝날 것으로 보지만 측정하지 않았다.

## 시험하지 않은 것과 위험

- 게시 이미지로 마이그레이션을 실행하지 않았다. 같은 소스 커밋으로 빌드한 jar와 소스를 썼다.
- 소셜 탈퇴 재인증(OAuth), PostHog 실제 수집, 실제 메일 수신, 검색 준비 실패 실주입, 운영 임베딩 서버 cold start 동작.
- 알려진 문제: 영어 화면 작업 목록에 서버 진행 단계(`PDF 1/1페이지 변환 완료`)가 한국어로 보인다. 운영에도 있던 문제다.

이 파일은 배포 성공 증명이 아니다.
