# 기동 전 중단의 무손실 복구 검토

[배포 실행](https://github.com/FruitionKR/Fruition-flatform/actions/runs/42583503648)은 Access/AI/Document migration 성공 후 after schema 지문 불일치로 중단됐다. 앱은 0 replicas와 503을 유지했고, 크레딧 면제 Job과 앱 rollout은 시작되지 않았다. 원래 검토 JSON과 immutable 시작·실패 기록을 수정하지 않는다.

원인은 기존 CHECK 제약식의 PostgreSQL dump/restore 재파싱이다. 운영의 `ANY ((ARRAY['x'::varchar, ...])::text[])`가 복원 DB에서는 `ANY (ARRAY[('x'::varchar)::text, ...])`로 출력된다. 새 migration의 변경 누락이나 실제 제약조건 차이로 취급해 통과시킨 것이 아니다.

검증은 세 DB 모두 다음과 같이 실제 실행했다. 원래 동결 백업을 격리 PostgreSQL 16.13에 복원하고 게시된 이미지로 migration해 원래 review의 after SHA256을 재현했다(pg_dump 16.15, restrict 토큰만 제거). 운영에서 추출한 after schema와 리허설 after schema를 각각 다른 빈 로컬 DB에 적용한 다음 같은 pg_dump로 내보냈다. 전체 schema 바이트가 일치했다. 데이터·계정·운영 접속정보를 저장소에 포함하지 않는다.

- access:
  - 원래 리허설: `1383de6e2c6588008d676df4e7a79576d0929c19c2770e58da3a394e4c86cc0a`
  - 운영 원문: `feb348cef42d270b15de2d8a6a146cd60c74525b2028995c05616c29796878d5`
  - 양쪽 재파싱 결과: `a9199e6750599c0e2e96e996aeb047585b818dd42ea6b78ffbbb273d61e1310e`
- document:
  - 원래 리허설: `5239db4ae7f9c432f0f73edba3a9c7e1d2434a0bdb6254c05388c645f651d4ce`
  - 운영 원문: `44e9582eb2b13d17e369f6b854f02163b7ec6a32fcbd863ae329a5ef87710bf3`
  - 양쪽 재파싱 결과: `2172a548e08e9abdad89e969ba51701320d384b972a76ffaf6b11c40b281cdb2`
- ai:
  - 원래 리허설: `f46374f6c70af56261600b335881cd2d83a2726272a588ff1753a17e17fec1b4`
  - 운영 원문: `722413a9efedfa0cf990053538ed5f6977f604a09f7520361bd37c251e97b379`
  - 양쪽 재파싱 결과: `f12baacc2af16b7c1bdb487856024c5b56ce7fc1447e7048e329ed7cca54c8f3`

복구는 `complete-before-rollout`로 명시하며 운영 원문 지문을 별도 plan에 고정한다. 기존 데이터 투영 해시가 모두 일치해야 하며, 기존 구 이미지 12개 중지·migration Job 세 개 성공·크레딧 면제 미시도·503·DB 세션 부재를 검사한다. 새 immutable recovery 시작 기록 후 면제 반영(기존 잔액/예약액/원장 유지), target 앱 기동, 인증 문서 편입 및 PDF smoke를 수행한다. migration SQL과 foundation은 다시 실행하지 않는다. 이전 기록 삭제나 원래 검토 지문 덮어쓰기는 없다.

재시작으로 로컬 임시 파일이 사라진 뒤 Access/Document 리허설을 암호화된 내구 백업에서 재구성했고, 세 DB 모두 원래 리허설 지문 재현과 schema 동일성 검증을 완료했다. 실제 운영 마이그레이션은 반복하지 않았다.
