# 2026-07-29 해결 이슈

## Backend — 문서 콘텐츠 버전 영속화와 diff

문서 본문을 `document_edit_states`와 `document_content_versions`에 영속화하고,
버전 목록·본문 조회·비파괴 복원 API를 제공한다. 수동 저장, AI 편집 적용, 복원으로
본문이 실제 변경될 때 변경 전·후 전체 Markdown 스냅샷을 보존한다.

두 버전의 전체 Markdown을 줄 단위로 비교해 GitHub 스타일의 변경 hunk를 반환하는
`GET /api/workspaces/{workspace_id}/documents/{document_id}/diff`를 추가했다.
응답에는 추가·삭제 줄 수와 각 줄의 `CONTEXT`, `DELETE`, `ADD` 구분 및 이전·이후
줄 번호가 포함된다.

### 확인 위치

- 저장과 버전 비교: `backend/src/main/java/fruition/document/service/DocumentService.java`의 `saveContent`, `compareContentVersions`
- diff 계산: `backend/src/main/java/fruition/document/service/MarkdownDiffService.java`
- API: `backend/src/main/java/fruition/document/controller/DocumentController.java`의 `compareVersions`
- 응답 계약: `backend/src/main/java/fruition/document/dto/DocumentContentDiffResponse.java`

### 검증

- `MarkdownDiffServiceTest`에서 추가·삭제·줄 번호와 동일 본문 결과를 검증했다.
- `DocumentServiceBlocksTest`에서 수동 저장·AI 적용·복원의 변경 전후 스냅샷과 버전 비교를 검증했다.
- `DocumentControllerTest`에서 diff API 응답 계약을 검증했다.
- `./gradlew test` 전체 테스트가 통과했다.

### 남은 작업

- 기존 데이터 중 변경 전 스냅샷이 없는 버전은 소급해 diff를 생성할 수 없다.
- Frontend 서버 API 연동은 `docs/issue/frontend/2026-07-23.md`에서 계속 관리한다.
