## Local-first evaluator 전환

- text evaluator를 제거하지 않고 로컬 판정의 fallback으로 이동했다.
- 깨진 문자와 유효하지 않은 Markdown 표는 로컬에서 바로 원본 검토 대상으로 만든다.
- 입력 PDF에서 재조립한 text-layout이 현재 표와 실질적으로 다르고 품질이 열화되지 않은 경우 로컬 근거로 처리한다.
- 나머지 애매한 표와 불완전 본문 후보만 text evaluator에 전달한다.
- 구현: `tmp/paper_ingest/paper2/designing_axial_flux_motor_outputs/scripts/evaluate_assembled_markdown.py`의 `needs_local_review`, `table_layout_disagrees`, `has_strong_table_layout_evidence`, `needs_text_fallback`, `evaluate`
- 테스트: `tmp/paper_ingest/paper2/designing_axial_flux_motor_outputs/tests/test_evaluate_assembled_markdown.py`의 local-first 및 table-layout evidence 테스트

- 수식, 그림, 다음 페이지 앞에서 정상적으로 끊긴 paragraph 20개를 복구 후보로 만들던 규칙을 제거했다.
- 고정된 최소 영단어 수, `a/an` 직접 Vision 판정, 마지막 연결 단어 목록을 제거했다.
- 깨진 문자와 표 구조 판정은 그대로 유지한다.
- 후보는 48개에서 28개, text evaluator 호출은 4회에서 3회, Vision 결과 block은 28개에서 26개로 줄었다.

- 불완전 종결 paragraph는 계속 제외하고, 구조 이상이 감지된 표는 text evaluator의 선택 없이 직접 Vision으로 확인하도록 변경했다.

## 문서 복원·평가 코드 DDD 이관

- `tmp/paper_ingest/.../scripts/`에서 검증한 canonical 문서 복원 경로를 `llmPipeline/app/modules/document_restoration/` bounded context로 이관했다.
- 단계 순서와 선택적 Vision 분기는 `application/restore_document.py`의 `RestoreDocumentUseCase`가 담당한다.

- 실행 진입점은 `interfaces/cli.py`이며 `python -m app.modules.document_restoration.interfaces.cli`로 실행한다.
- local-first evaluator는 `llmPipeline/app/modules/document_evaluation/infrastructure/local_document_evaluator.py`로 이관하고 CLI parsing은 `interfaces/local_cli.py`로 분리했다.
- 외부 evaluator job 생성 CLI는 `llmPipeline/app/modules/document_evaluation/interfaces/cli.py`로 이동했다.
- 복원 prompt는 `llmPipeline/prompts/document_restoration/`에 모았다.
- 실험 스크립트, PDF, crop, model cache, 실행 산출물은 제품 코드와 분리하고 `/tmp/`, `/paddle_cache/`를 Git 추적 대상에서 제외했다.
