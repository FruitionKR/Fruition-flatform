# 2026-08-07 backend 이슈

## [미해결] requestProcessingAfterCommit도 afterCommit+REQUIRED 패턴 — INSERT 유실 의심

converter 연결 중 실측으로 확인한 버그: `afterCommit()` 콜백 안에서 기본(REQUIRED) `TransactionTemplate`으로
INSERT하면 바깥(이미 커밋된) 트랜잭션 리소스에 참여해 **커밋되지 않고 조용히 버려진다**
(로그는 찍히는데 행이 없음). `DocumentService.requestConvertAfterCommit`은 REQUIRES_NEW로 수정 완료.

같은 패턴이 `DocumentService.requestProcessingAfterCommit`(라인 664 근방, `document_processing_queue`)에도
그대로 있다 — @Transactional 경유 호출 시 큐 등록이 유실될 가능성. 사용 경로 확인 후 동일하게
REQUIRES_NEW 적용 필요 (이번 작업 범위 밖 기존 코드라 미수정).

## [미해결] 권한 guard 우회 의심 현상 1회 관찰 (재현 불가)

로컬 컨테이너 스택(colima 재기동 직후의 document-svc 프로세스)에서 아래 조건인데 문서 목록/생성이 200/201로 응답:

- Redis `authz:role:{wid}:{uid}` 키 삭제 확인 (`EXISTS`=0, MONITOR로 앱의 GET 관측)
- access-svc 컨테이너 정지 (내부 API 폴백 불가 — 컨테이너 내부 wget으로 unreachable 확인)
- 기대 동작: `WorkspaceAccessGuard.requireMember` fail-closed 404 (`docs/msa/current-architecture.md` §3)

**document-svc 컨테이너 재시작 후에는 스펙대로 동작** (같은 조건 404, access 복구 시 폴백→OWNER 캐시 TTL 300 재적재, 가짜 workspace 404, 무토큰 401 전부 정상). 이후 재현 불가.

- 관찰 시점: colima 재기동으로 되살아난 구 프로세스에서만 발생. 재시작 후 소멸.
- 코드 검토상 guard(`fruition/core/authz/WorkspaceAccessGuard.java`)에 in-process 캐시 없음 — 원인 미상.
