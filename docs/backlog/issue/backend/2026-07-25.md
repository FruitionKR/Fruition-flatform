## 계층 트리 삭제·복구

### 현재 범위

- Core `TASK-008`은 문서 한 건의 소프트 삭제·휴지통·복구를 제공한다.
- 개별 복구 문서는 최상위 마지막 위치에 배치한다.
- workspace 소프트 삭제는 하위 문서·채팅·Wiki·멤버십을 변경하지 않고 workspace 접근 경계만 닫는다.

### 후속 작업

- 폴더 삭제 시 전체 하위 폴더와 포함 문서를 같은 `delete_operation_id`로 소프트 삭제한다.
- 전체 트리 복구는 기존 부모와 순서를 복원한다.
- 하위 폴더·문서 개별 복구는 최상위 마지막 위치에 배치한다.
- 문서는 leaf이므로 개별 소프트 삭제·복구한다.
- 폴더 트리 삭제·복구를 구현한다.
- 영구 삭제 보존 기간과 실행 주체를 결정한다.

## Markdown 외 문서 형식 확장

### 현재 범위

- 업로드 API는 형식을 제한하지 않는다.
- Markdown은 편집 상태와 원본을 `uploaded` 상태로 저장하며, 사용자가 재ingest API를 호출할 때만 Wiki pipeline을 실행한다.
- 비-Markdown은 `uploaded` 상태의 읽기 전용 원본으로 저장하고 변환 pipeline을 실행하지 않는다.
- Markdown 원문 내보내기는 구현되었으며, 다른 형식 내보내기는 지원하지 않는다.

### 후속 작업

- PDF, DOCX 등 원본 자료의 지원 형식과 MIME 정책을 정의한다.
- 기존 `llmPipeline`의 PDF 문서 복원 CLI를 worker 또는 API로 연결하고 저장 경로를 정의한다.
- 변환 작업의 run ID를 Wiki 생성 pipeline run ID와 분리한다.
- 변환 결과 callback의 인증, 멱등성, checksum 및 크기 제한 계약을 정의한다.
- 변환 완료 후 Wiki pipeline을 시작하는 순서를 정의한다.
- PDF 등 Markdown 외 내보내기 형식과 이미지·첨부 자원의 포함 정책을 정의한다.
- PDF를 `.md` 복제본으로 만드는 기능은 변환 편집본 등록이 완료된 뒤 `POST /duplicate`와 연결한다.

### 기존 코드와의 충돌

현재 backend는 파일 종류와 관계없이 업로드 시 원본만 `uploaded` 상태로 저장한다. 편집 가능한 Markdown은 사용자가 재ingest API를 호출할 때 Wiki pipeline을 시작한다. `llmPipeline`의 `POST /pipeline/runs`는 PDF 변환 API가 아니며, `extracted_text_uri`가 없는 비-Markdown 문서를 처리하지 못한다. 향후 지원할 때 변환 worker 시작과 Wiki pipeline 시작을 분리해야 한다.

## 직접 생성 Markdown의 레거시 `/original` 계약

### 현재 범위

- `GET /api/workspaces/{workspace_id}/documents/{document_id}/original`은 `source_uri`가 있는 업로드 원본을 MinIO에서 스트리밍한다.
- 직접 생성 Markdown은 `source_uri=null`이므로 현재 `404 DOCUMENT_ORIGINAL_NOT_FOUND`를 반환한다.
- 최신 Markdown 원문 다운로드는 `GET /api/workspaces/{workspace_id}/documents/{document_id}/export`로 제공한다.

### 후속 작업

- 레거시 `/original`에서도 직접 생성 문서의 최신 편집 상태를 `text/markdown`으로 반환할지 결정한다.
- 지원한다면 업로드 원본 조회와 최신 편집본 내보내기의 역할 중복을 정리하고 회귀 테스트를 추가한다.
