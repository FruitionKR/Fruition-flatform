# 2026-08-06 Backend 이슈 — AWS 배포 준비 잔여 작업

2026-08-06에 MSA Phase 0~2 일부(deny-by-default, JWT iss·aud, 인가 단일화, V20 workspace_id, Redis 상태 외부화, timeout·내부 토큰)를 적용했다(`docs/changelog/backend.md` 2026-08-06 참조). 아래는 아직 남은 작업이다. 기준 문서: `docs/backlog/Fruition_MSA_Proposal_revised.md`, `docs/Fruition_AWS_MSA_Architecture.md`.

## 1. refresh token 재사용 탐지 (계열 전체 무효화)

- 현재 refresh는 opaque·SHA-256 hash·회전까지 구현됨(`AuthService.java`). 이미 폐기된 refresh 재제출 시 `InvalidRefreshTokenException`만 던지고 계정의 나머지 유효 refresh를 무효화하지 않는다.
- 토큰 탈취 시나리오 방어를 위해 재사용 감지 시 해당 사용자 refresh 계열 전체를 폐기하는 로직 추가 필요.

## 2. RS256 + JWKS 전환

- 현재 HS256 + iss·aud 검증. access-svc를 별도 서비스로 분리하는 시점(Phase 3)에 RS256 서명·JWKS 공개·key 회전 중첩을 도입한다. 단일 서비스 동안에는 불필요.

## 3. Spring Session jdbc 정리

- `spring.session.store-type=jdbc`로 업무 DB에 세션 저장 중. OAuth2 로그인 redirect 흐름에만 세션이 필요하므로, access-svc 분리 시 세션 저장을 함께 정리(Redis session 또는 무세션화)한다.

## 4. Rate limiting / Workspace별 quota

- 엔드포인트 rate limit과 Workspace별 요청·비용 한도 없음. 제안서 §6.2~6.3 참조. Redis 도입으로 저장 기반은 마련됨.

## 5. Document 편집 저장소 MongoDB 전환 (Phase 1 문서 목표)

- 현재 PostgreSQL `document_edit_states`+`document_content_versions`로 동작 중이며 기능상 문제 없음. 문서 목표(MongoDB 이관)는 backfill·cutover 비용 대비 이득을 재평가한 뒤 결정.

## 6. retry·circuit breaker

- pipeline client는 공용 timeout까지만 적용됨. 재시도(한 계층, backoff·jitter)와 provider·경로별 circuit breaker는 미구현(제안서 §5.1).
