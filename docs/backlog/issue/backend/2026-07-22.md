# 2026-07-22 Backend 이슈

## 1. [Backend 해결] workspace 폴더 트리 영속화 API

2026-07-25 기준 backend 구현으로 해소됐다. 상세는 [`docs/issue/backend/2026-07-23.md`](2026-07-23.md)의 `1. [Backend 해결] workspace 폴더 트리 영속화 API`와 [`docs/backlog/issue-2026-07-25.md`](../../../../../../docs/backlog/backlog/issue-2026-07-25.md)의 `Backend — 폴더 트리 영속화 API` 참조. frontend 재배선(H007)만 남는다. 이전 요구 배경은 아래에 유지한다.

왼쪽 사이드바는 문서와 폴더를 계층형 트리로 표시하고, 프로젝트 사이에서 문서·하위 폴더를 이동할 수 있다. 그러나 backend에는 폴더를 생성하거나 트리 배치와 정렬 순서를 저장하는 API가 없다.

### 현재 상태

- backend의 문서 목록 API는 workspace 문서를 flat list로 반환한다.
- frontend는 최상위 폴더를 `Project`, 하위 항목을 `TreeItem`으로 관리한다.
- 폴더 생성, 이름 변경, 삭제, 문서·폴더 이동 결과는 workspace별 `localStorage`에 임시 저장한다.
- 따라서 같은 브라우저에서는 새로고침 후 복원되지만, 다른 브라우저·기기·협업자에게는 동기화되지 않는다.
- backend에서 삭제된 문서와 새로 추가된 문서만 문서 목록 응답을 기준으로 frontend 트리에 재동기화한다.

### 필요한 API 계약

endpoint 이름과 응답 DTO는 구현 전에 최종 확정하되 다음 동작을 workspace 범위에서 제공해야 한다.

- `GET /api/workspaces/{workspace_id}/document-tree`
  - 폴더 계층, 문서 배치, 같은 부모 안의 정렬 순서를 반환한다.
- `POST /api/workspaces/{workspace_id}/folders`
  - 폴더 이름, 선택적 상위 폴더 ID와 정렬 위치를 받아 폴더를 생성한다.
- `PATCH /api/workspaces/{workspace_id}/folders/{folder_id}`
  - 폴더 이름, 상위 폴더와 정렬 위치를 변경한다.
- `DELETE /api/workspaces/{workspace_id}/folders/{folder_id}`
  - 비어 있지 않은 폴더의 삭제 정책을 명시하고 적용한다.
- `PATCH /api/workspaces/{workspace_id}/documents/{document_id}/placement`
  - 문서의 폴더 ID와 정렬 위치를 변경한다. 최상위 배치는 `folder_id: null`로 표현한다.

폴더와 문서 이동을 하나의 트리 mutation endpoint로 제공하는 방식도 가능하지만, frontend가 전체 트리를 덮어쓰지 않고 충돌을 감지할 수 있도록 version 또는 `updated_at` 기반 조건부 변경 계약이 필요하다.

### Backend 구현 작업

1. workspace 소유 폴더 entity와 자기 참조 parent 관계를 추가한다.
2. 같은 부모 안의 폴더·문서 정렬 순서를 저장할 모델을 정의한다.
3. 폴더 생성·이름 변경·이동·삭제와 문서 배치 변경을 transaction으로 처리한다.
4. 폴더를 자기 자신이나 자신의 하위 폴더로 이동하는 순환 구조를 차단한다.
5. 모든 조회·변경에서 workspace 구성원 권한과 대상 folder/document 소속을 검증한다.
6. 문서 업로드 시 기본 배치 위치와 폴더 삭제 시 포함 문서 처리 정책을 확정한다.
7. 동시 이동·이름 변경 충돌 응답을 정의한다.

### 완료 조건

- 폴더 생성 후 로그아웃·재로그인하거나 다른 브라우저에서 접속해도 동일한 트리가 조회된다.
- 문서와 하위 폴더를 같은 프로젝트 및 다른 프로젝트로 이동한 결과가 유지된다.
- 폴더·문서의 형제 정렬 순서가 유지된다.
- 다른 workspace의 folder/document를 조회하거나 변경할 수 없다.
- 순환 이동, 존재하지 않는 parent, 비어 있지 않은 폴더 삭제, 동시 변경 충돌이 backend 테스트로 검증된다.
- frontend가 `localStorage`를 원본 저장소로 사용하지 않고 backend 응답으로 트리를 복원한다.

### Frontend 임시 구현과 후속 연결

- 현재 frontend는 `fruition.project_tree.{workspace_id}` 키에 폴더 트리를 임시 저장한다.
- API가 준비되면 `useProjectTree`의 초기 복원과 변경 저장을 backend 호출로 교체한다.
- offline 또는 낙관적 UI가 필요하면 `localStorage`는 원본이 아닌 cache로만 사용한다.
- 변경 실패 시 frontend가 이전 트리로 원복할 수 있도록 backend 오류 code를 안정적으로 제공한다.

### 확인 위치

- frontend 트리 상태·임시 저장: `frontend/app/_hooks/useProjectTree.ts`의 `PROJECT_TREE_STORAGE_PREFIX`, `loadPersistedProjects`, `persistProjects`
- frontend 프로젝트 간 이동: `frontend/app/_lib/tree.ts`의 `moveProjectTreeItem`
- frontend backend 문서 재동기화: `frontend/app/_lib/tree.ts`의 `mergeBackendDataIntoProjects`
- 현재 문서 API client: `frontend/app/_lib/api.ts`의 `fetchBackendData`
- 기존 API 범위: `docs/backlog/Fruition_MVP_API_Contract.md`의 `10. MVP 제외` 내 `폴더형 파일 트리`

## 2. Markdown Agent turn production 동시성·대화 context 후속

Spring의 `POST /api/workspaces/{workspace_id}/agent/turn` 프록시는 구현됐다. workspace·document 접근 권한과 Markdown 문서 여부를 확인하고, `editorSnapshot`을 `active_markdown_context`로 변환해 `llmPipeline`의 `POST /agent/turn`을 호출한다. pipeline의 400/422 응답은 보존하며 결과에 `documentId`, `baseVersion`, `requestId`를 붙인다.

### 남은 Backend 작업

1. 현재 local profile 메모리 mock인 문서 content 저장을 영속 저장소로 교체한다.
2. Agent 요청의 `baseVersion`을 영속 저장된 현재 content version과 비교하고 오래된 요청을 `409`로 거절한다.
3. Agent 요청을 chat session과 연결하고, 최근 대화 요약과 reference context를 Backend에서 구성한다.
4. production content 저장 API까지 포함한 권한·version·timeout 통합 테스트를 추가한다.

### 완료 조건

- 오래된 `baseVersion` 요청이 pipeline 호출 전에 충돌 응답으로 거절된다.
- chat session 기반 요청에서 실제 최근 대화와 reference context가 pipeline에 전달된다.
- Apply 이후 영속 content 저장 API의 optimistic locking으로 version 증가와 충돌이 검증된다.

### 확인 위치

- 전체 계약: `docs/spec/agent-markdown-contract.md`의 `Frontend → Spring backend`, `Spring backend → llmPipeline`, `오류 처리`
- Spring endpoint: `backend/src/main/java/fruition/agent/controller/AgentTurnController.java`의 `POST /turn`
- pipeline 변환: `backend/src/main/java/fruition/agent/repository/PipelineAgentRequester.java`
- frontend 호출: `frontend/app/_lib/api.ts`의 `requestAgentTurn`
- pipeline endpoint: `llmPipeline/app/modules/agent/interfaces/http/routes.py`의 `POST /agent/turn`
- local content version mock: `backend/src/main/java/fruition/document/controller/LocalNoteContentMockController.java`
