# 2026-07-24 Frontend 이슈

## Markdown 수동 저장·페이지 제목 변경 API 연동

### 배경

backend의 local 메모리 content mock을 production DB 저장 API로 교체하고, 페이지 제목을 본문 heading과 분리하는 Notion식 rename 계약을 적용했다. frontend 코드는 backend task에서 변경하지 않는다.

### 필요한 작업

- 저장 버튼과 `Cmd/Ctrl+S`가 `PUT /api/workspaces/{workspace_id}/documents/{document_id}/content`를 호출하게 한다.
- 요청은 `multipart/form-data`의 `markdown`, `base_version` 필드를 사용한다.
- 응답의 `changed`, `current_version`, `content_hash`, `updated_at`을 편집 상태에 반영한다.
- `409 DOCUMENT_VERSION_CONFLICT`에서 최신 문서를 다시 불러오도록 안내한다.
- 문서 제목 변경은 `PATCH /api/workspaces/{workspace_id}/documents/{document_id}/rename`에 `display_name`, `base_version`을 전달한다.
- 기존 `filename`, `sync_source_title`, `expected_content_version` 요청 필드 사용을 제거한다.
- 제목 변경은 Markdown 첫 heading과 Wiki Source Page 제목을 바꾸지 않는다는 UI 정책을 적용한다.
- 소유자가 아닌 멤버의 `403 DOCUMENT_WRITE_FORBIDDEN`을 읽기 전용 UI로 처리한다.
- 미저장 상태에서 문서 이동·새로고침·종료 시 이탈 경고를 제공한다.

### API 확인 위치

- `backend/src/main/java/fruition/document/controller/DocumentController.java` — `PUT /content`, `PATCH /rename`
- `backend/src/main/java/fruition/document/dto/DocumentContentSaveResponse.java`
- `backend/src/main/java/fruition/document/dto/DocumentRenameRequest.java`
- `backend/src/main/java/fruition/document/dto/DocumentRenameResponse.java`

## Markdown 문서 복제 API 연동

### 필요한 작업

- 문서 소유자에게만 복제 동작을 제공한다.
- `POST /api/workspaces/{workspace_id}/documents/{document_id}/duplicate` 요청에 매 시도마다 유지되는 `Idempotency-Key`를 전달한다.
- 성공 응답의 `id`, `parent_document_id`, `sort_order`를 사용해 같은 부모의 마지막에 새 페이지를 추가한다.
- 서버가 정한 `복사본 (N)` 이름을 응답의 `display_name`, `filename` 그대로 표시한다.
- 원본 자료와 소유자가 아닌 문서의 `403 DOCUMENT_WRITE_FORBIDDEN`을 복제 불가 UI로 처리한다.
- 현재 PDF 원본은 복제 대상이 아니며, 변환 편집본 기능이 추가되기 전까지 복제 UI를 노출하지 않는다.

### API 확인 위치

- `backend/src/main/java/fruition/document/controller/DocumentController.java` — `POST /duplicate`
- `backend/src/main/java/fruition/document/dto/DocumentDuplicateResponse.java`
