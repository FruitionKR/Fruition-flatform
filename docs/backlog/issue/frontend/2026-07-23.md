## 6. access token 자동 재발급(refresh) 연동

- `apiFetch`가 401을 즉시 "로그인 필요" 에러로 던져 access token(15분) 만료마다 재로그인이 필요하다. `frontend/app/_lib/auth.ts:5`에 TODO로 남아 있다.
- `apiFetch` 401 시 저장된 refresh token으로 재발급을 1회 시도하고, 원요청을 재시도한 뒤 실패한 경우에만 로그인 화면으로 보낸다. 재발급된 토큰은 `saveTokens`로 교체한다.
- Backend 구현 완료: `POST /api/auth/refresh` — refresh 검증 후 access/refresh 재발급, 기존 refresh 폐기 (`backend/.../user/controller/AuthController.java:132`). 프론트 연결 지점: `frontend/app/_lib/api.ts:52`(apiFetch), `frontend/app/_lib/auth.ts:20`(saveTokens).

## 7. 서버 로그아웃 연동

- `handleLogout`이 localStorage 토큰만 삭제하고 Backend를 호출하지 않아 refresh token이 서버에 남는다.
- 로그아웃 시 저장된 refresh token으로 `POST /api/auth/logout`을 호출해 서버 토큰을 폐기한 뒤 로컬 토큰을 삭제한다.
- Backend 구현 완료: `POST /api/auth/logout` — refresh token 폐기 (`backend/.../user/controller/AuthController.java:143`). 프론트 연결 지점: `frontend/app/_components/document-sidebar/SidebarProfile.tsx:26`(handleLogout).

## 8. 채팅 위키화 부분 선택(partial) 연동

- `exportChatWiki()`가 `selection_mode:"full"`, `pair_ids:[]`를 고정 전송해 항상 세션 전체만 위키화한다.
- 문답(pair) 선택 UI를 추가하고 선택 시 `selection_mode:"partial"`과 `pair_ids`를 전달한다.
- Backend 구현 완료: `selection_mode` full/partial과 `pair_ids` 발췌 지원 (`backend/.../chat/service/ChatWikiExportService.java:123`, DTO `backend/.../chat/dto/ChatWikiExportRequest.java`). 프론트 연결 지점: `frontend/app/_lib/api.ts`(exportChatWiki).

## 9. 다중 채팅 세션 목록·전환 UI

- 항상 최신 세션을 자동 선택/생성하고(`sessionCache`) 세션 전환·목록 UI가 없다.
- 세션 목록을 표시하고 선택·생성할 수 있는 UI를 추가한다. 조회 API는 `fetchChatSessions()`로 이미 준비돼 있다.
- Backend 구현 완료: 워크스페이스당 최대 10개 세션, 목록/생성 API (`backend/.../chat/service/ChatSessionService.java:20`). 프론트 연결 지점: `frontend/app/_lib/api.ts`(getSessionContext).

## 11. Auth 라이브 4흐름 브라우저 검증 (스트림1 P0 잔여)

인증 스트림(`docs/issue/frontend/2026-07-23-parallel-streams/stream1-auth.md`)의 P0 정적 검증은 완료했다. 화면↔API 매핑을 코드로 재확인했고 `npm run lint` / `tsc --noEmit` / `npm run build` 전부 통과했다. **잔여**: 실제 브라우저 라이브 4흐름 구동·스크린샷은 Backend(Spring `localhost:8080`)+DB 기동이 필요해 이번에 수행하지 못했다. 아래 수동 체크리스트로 이관한다.

Backend 기동(`localhost:8080`) → `frontend`에서 `npm run dev` → `localhost:3000`. 로컬은 인증번호 `9700` 자동인증으로 통과.

- [ ] 로그인(이메일): 정상 토큰 저장 후 `/workspaces` 리다이렉트. 오입력 시 "가입하지 않은 아이디거나, 잘못된 비밀번호입니다." 노출
- [ ] 로그인(OAuth): `?code=` 콜백 → `exchangeOAuthCode` → 토큰 저장·리다이렉트
- [ ] 회원가입 3스텝: 요청(`/signup`)→인증(`/signup/verify`, `9700` 자동)→가입+자동로그인→`/workspaces`. **중복 이메일 409 메시지 노출 확인**
- [ ] 비밀번호 찾기: 요청→인증(`/forgot-password`)→재설정(`/reset-password`)→`/login`. 재설정 후 기존 세션 revoke 확인
- [ ] 엣지(아래 §11-1) 재현·확인

### 11-1. 가입 성공 후 자동 로그인 실패 시 오표시 (UX 미처리)

`signup/verify/page.tsx:43-55`에서 `signupWithEmail` 성공 후 `loginWithEmail`이 실패하면 catch가 "회원가입에 실패했습니다."를 표시한다. 그러나 계정은 이미 생성된 상태라 메시지가 오해를 준다. 재로그인 유도(로그인 화면 이동) 또는 "가입은 완료됐습니다. 로그인해 주세요." 류 분기가 필요하다. 스펙 확정 후 반영 대상.
