# 2026-07-28 Frontend 이슈

## 개발 도구 의존성 보안 경고와 ESLint CLI 전환

### 현재 상태

- production 의존성은 `postcss 8.5.24` override 적용 후 `npm audit --omit=dev`가 0건이다.
- 전체 `npm audit`에는 ESLint 8 도구 체인의 `glob`, `minimatch`, `brace-expansion` 경로에서
  high 경고 13건이 남는다.
- `npm audit fix --force`는 ESLint 10 등 breaking 변경을 제안하므로 현재 Next.js 15 설정에
  자동 적용하지 않았다.
- `next lint`는 Next.js 16에서 제거될 예정이라는 deprecation 경고를 출력한다.

### 후속 작업

- Next.js와 `eslint-config-next`의 지원 조합을 확인해 ESLint CLI 설정으로 전환한다.
- ESLint 9 이상 전환 후 dev dependency audit를 다시 실행하고, 잔여 경고가 없도록 lockfile을
  갱신한다.
- `npm run lint`, `npm run test:markdown`, `npm run test:user-preferences`, `npm run build`를
  회귀 검증한다.

### 관련 코드와 확인 위치

- `frontend/package.json` — `lint`, `eslint`, `eslint-config-next`, `overrides`
- `frontend/package-lock.json` — dev dependency 해석 결과
- Next.js 실행 경고 — `npm run lint`

## 워크스페이스 초기 진입 시 인증 요청 경합 처리

### 현재 상태

- `/workspaces` 최초 렌더링은 API 응답 전 실패 화면이 아니라
  `LoadingOverlay`를 표시하며, `GET /api/workspaces`가 실패한 뒤에만 오류 화면으로 전환된다.
- 로그인 직후 `WorkspacesPage`의 `GET /api/workspaces`와 전역
  `UserPreferencesProvider`의 `GET /api/auth/me`가 병렬로 실행된다.
- 동일한 Spring Session을 사용하는 조건에서 두 요청 중 하나가 `500`으로 실패하는 현상을
  재현했다. 요청 순서에 따라 `GET /api/workspaces`가 실패하면 최초 진입에서 오류 화면이
  표시되고, 재시도 시 정상 진입할 수 있다.
- 근본 원인과 backend 수정 범위는
  `docs/issue/backend/2026-07-28.md`의
  **JWT 인증 요청의 Spring Session 저장 경합**을 참조한다.

### 후속 작업

- backend의 JWT 인증 경로를 stateless로 분리한 뒤 로그인 → `/workspaces` → `/home` 흐름을
  실제 브라우저에서 반복 검증한다.
- `GET /api/workspaces`와 `GET /api/auth/me`가 병렬 실행돼도 워크스페이스 오류 화면이
  표시되지 않는지 확인한다.
- backend 수정과 별개로 일시적 `5xx` 자동 재시도를 도입할지는 UX 정책으로 결정한다.
  자동 재시도는 서버 세션 경합의 근본 해결로 간주하지 않는다.

### 완료 조건

- 정상 로그인 직후 `/api/workspaces`가 `200`으로 완료되고 `/home`으로 한 번에 이동한다.
- 병렬 `/api/auth/me` 호출의 성공 여부가 워크스페이스 진입에 영향을 주지 않는다.
- 실제 `GET /api/workspaces` 실패 시에만 중앙 오류 화면이 표시되고, 재시도 버튼이 동작한다.
