# 2026-07-28 AI 이슈

## 1. Wiki 페이지 이름 변경 API 구현

Spring backend의 외부 API `PATCH /api/workspaces/{workspace_id}/wiki/pages/{wiki_page_id}/rename`은 워크스페이스 멤버십만 검증한 뒤 llmPipeline으로 요청을 위임한다. llmPipeline이 아직 내부 rename API를 제공하지 않으므로 다음 계약을 구현해야 한다.

### 필요한 API 계약

- **method/path**: `PATCH /wiki/pages/{wiki_page_id}/rename`
- **요청 body**:
  - `user_id`: 요청 사용자 ID
  - `workspace_id`: 대상 워크스페이스 ID
  - `title`: 변경할 제목
  - `update_slug`: 제목에 맞춰 slug도 변경할지 여부
- **성공 응답**:
  - `id`, `page_type`, `title`, `previous_title`
  - `slug`, `previous_slug`, `slug_updated`, `updated_at`
- **오류 응답**:
  - 잘못된 제목: `400`
  - 페이지가 없거나 `user_id`·`workspace_id` 소속이 다름: `404`
  - 같은 사용자·워크스페이스·페이지 타입 안의 slug 충돌: `409`

### 구현 요구사항

1. `wiki_page_id`, `user_id`, `workspace_id`를 함께 사용해 대상 페이지 소속을 검증한다.
2. 제목은 trim 후 1자 이상 255자 이하인지 검증한다.
3. `update_slug=true`일 때 기존 Spring 규칙과 동일하게 slug를 생성한다.
   - 소문자화
   - 공백을 `-`로 변환
   - 영문 소문자·숫자·한글·`-` 외 문자 제거
   - 연속 및 앞뒤 `-` 제거
4. slug 충돌 검사는 `(user_id, workspace_id, page_type, slug)` 범위로 수행한다.
5. 페이지 조회, 충돌 검사, 제목·slug UPDATE를 하나의 DB 트랜잭션에서 처리한다.
6. Spring의 `WikiPageRenameResponse`와 호환되는 snake_case JSON을 반환한다.

### 완료 조건

- 정상 요청에서 title만 변경하거나 title과 slug를 함께 변경할 수 있다.
- 다른 사용자·워크스페이스의 페이지는 변경할 수 없다.
- slug 충돌 시 어떤 필드도 부분 변경되지 않는다.
- 같은 slug로 재요청해도 충돌하지 않고 `slug_updated=false`를 반환한다.
- 잘못된 제목, 페이지 부재, slug 충돌과 정상 변경을 자동화 테스트로 검증한다.

### Backend 확인 위치

- 외부 API: `backend/src/main/java/fruition/wiki/controller/WikiController.java`의 `PATCH /pages/{wiki_page_id}/rename`
- 위임 서비스: `backend/src/main/java/fruition/wiki/service/WikiService.java`의 `rename`
- pipeline client: `backend/src/main/java/fruition/wiki/repository/PipelineWikiPageRequester.java`

## 2. AI 응답 개인 설정 계약

### 목표

Query와 Agent 답변에 사용자 기본 언어·분량·외부 웹 검색 허용 여부를 일관되게 적용한다.
문서 생성·편집은 문서 언어를 임의로 바꾸지 않도록 채팅 답변과 별도 규칙을 둔다.

### 제안 입력

```json
{
  "output_language": "ko",
  "response_length": "balanced",
  "allow_web_search": false
}
```

- `output_language`: `ko | en | document`
- `response_length`: `concise | balanced | detailed`
- `allow_web_search`: 이번 요청에서 외부 검색을 허용했는지 나타내는 boolean
- 모든 필드는 optional로 추가해 기존 backend 요청과 호환한다.

### 적용 규칙

- 채팅 답변은 `output_language`를 우선하되, 인용문·코드·고유명사는 원문을 유지한다.
- `document`는 현재 편집 대상 또는 검색 근거 문서의 주 언어를 따른다. 판단 근거가 없으면
  질문 언어를 사용한다.
- `response_length`는 목표 설명 밀도이지 사실·인용·필수 경고를 생략하는 토큰 상한이 아니다.
- Markdown 편집은 기존 문서 언어와 문체를 유지한다. Markdown 생성은 사용자 요청에
  명시된 언어를 우선하고, 없을 때만 `output_language`를 사용한다.
- `allow_web_search=false`이면 evaluator가 `web_fallback`을 선택하지 못하게 한다.
- `allow_web_search=true`여도 `QUERY_WEB_SEARCH_MODE=disabled`이면 검색 기능은 사용할 수 없다.

### 후속 작업

- `QueryRequest`와 Agent turn schema/domain entity에 optional 필드를 추가한다.
- Query answer generator/evaluator와 Agent router prompt에 적용하되, 데이터 값은 명령이
  아니라 신뢰된 preference 필드로 구조화해 전달한다.
- 내부 Wiki 근거만으로 답한 경우와 web fallback을 사용한 경우 모두 언어·분량 정책을 검증한다.
- 문서 언어 판별 실패, 설정 누락, 지원하지 않는 enum의 fallback 규칙을 테스트한다.

### 완료 조건

- Query와 Agent 채팅 답변이 동일한 언어·분량 의미를 사용한다.
- Markdown 편집에서 설정 때문에 원문 언어가 불필요하게 번역되지 않는다.
- `allow_web_search=false`에서 web search port가 호출되지 않는다.
- 필드가 없는 기존 요청의 출력과 회귀 테스트가 유지된다.
