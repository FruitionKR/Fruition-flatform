### 교차 트랜잭션 4곳 (원자성·잠금 의존)

- `finish_pipeline_run` (`postgres_wiki_ingestion_repository.py:150-193`): documents `FOR SHARE` 잠금 + core/ai write 혼합 단일 트랜잭션
- `_persist_wiki_outputs` (`postgres_wiki_output_persistence.py`): wiki_pages(core) write와 임베딩 유닛(ai) write가 페이지 단위 인터리브
- `fail_pipeline_run` (`:196-219`): documents·pipeline_runs 상태 동시 갱신
- wiki lint/maintenance (`wiki_maintenance.py:40-96`): 후보 조회→구조 정리→승격이 한 트랜잭션, 실패 보상도 롤백 의존

### DB 제약

- V4 물리 FK 4건: pipeline_runs→documents, wiki_page_embeddings→wiki_pages, wiki_embedding_units→wiki_pages/documents
- CASCADE 삭제 의존: wiki_pages/documents 삭제 시 임베딩 자동 정리 — 분리 시 대체 경로(이벤트/배치) 필요

## 이전하려면 (후속 설계 과제)

1. 검색 쿼리 재설계: CTE의 core⋈ai JOIN을 2단계 조회(+앱 조인)로, 또는 검색 projection을 ai_db로 복제
2. ingest 원자성 재설계: FOR SHARE 잠금 제거 → saga/보상 или `document.edit.event` 기반 정합
3. CASCADE 대체: 문서/페이지 삭제 이벤트 소비로 임베딩 정리
4. 완료 후 V4/V6 DDL을 ai 스키마(`services/ai-svc/pipeline/db/ai_schema.sql`)로 이관
