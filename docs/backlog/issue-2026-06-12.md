## 프론트엔드 해결 이슈

### 1. 문서와 Wiki page 이름 변경 API 필요

- 대상:
  - `PATCH /api/documents/{document_id}/rename`
  - `PATCH /api/wiki/pages/{wiki_page_id}/rename`
- 현상:
  - 프론트 왼쪽 트리에서 문서, source page, concept page 이름을 변경해도 현재는 프론트 메모리 상태에만 반영된다.
  - 새로고침하거나 `GET /api/documents`, `GET /api/wiki/graph`를 다시 조회하면 백엔드 응답의 기존 `filename`, `title`로 되돌아간다.
- 원인:
  - 원본 문서 표시명은 `documents.filename`에서 내려온다.
  - source/concept 표시명은 `wiki_pages.title`에서 내려온다.
  - 현재 API 계약에 이 두 값을 사용자가 변경해 저장할 endpoint가 없다.
- 필요한 이유:
  - 프론트 localStorage override만으로 처리하면 사용자 기기별 임시 표시명만 바뀌고, 협업자나 다른 브라우저에는 반영되지 않는다.
  - graph node label, 왼쪽 트리 label, 상세 페이지 title, 검색 결과 title이 서로 다른 이름을 표시할 수 있다.
  - source page는 원본 raw 문서와 1:1로 매핑되므로, 문서명 변경과 source title 변경의 관계를 백엔드에서 명확히 관리해야 한다.
- 해결 방향:
  - 원본 문서명 변경은 `documents.filename`만 갱신하고 `source_uri`, content hash, MinIO object key는 변경하지 않는다.
  - Wiki page명 변경은 `wiki_pages.title`을 갱신하고 필요 시 slug 변경 여부를 API 옵션으로 명시한다.
  - rename 요청/응답에는 변경 전후 이름, 변경된 시각, slug 변경 여부를 포함한다.
  - 이름 중복, 빈 문자열, 과도한 길이, path separator 포함 문자열을 검증한다.
  - source page title을 원본 문서 filename과 자동 동기화할지, 사용자가 별도 수정할 수 있게 둘지 정책을 확정한다.
