# 2026-07-16 Backend 이슈

2026-07-16 backend + llmPipeline 전체 API 호출 점검 중 발견한 스키마 이슈와 조치를 기록한다.

## 1. wiki_pages 잔재 unique constraint `uq_wiki_pages_type_slug` 제거

### 문제

- `wiki_pages`에 unique constraint 2개가 공존하는 DB가 있었다.
  - `uq_wiki_pages_workspace_type_slug (user_id, workspace_id, page_type, slug)` — 현행. `fruition/wiki/domain/WikiPage.java`에 정의됨.
  - `uq_wiki_pages_type_slug (page_type, slug)` — 과거 entity 정의의 잔재. 현재 코드 어디에도 정의 없음. `ddl-auto=update`는 기존 constraint를 삭제하지 않아 DB에만 남아 있었다.
- 영향: llmPipeline이 wiki page를 workspace 단위 constraint 대상으로 upsert(`ON CONFLICT (user_id, workspace_id, page_type, slug)`)하는데, 잔재 constraint가 전역 `(page_type, slug)` 중복을 먼저 막아 문서 재실행 run이 `duplicate key value violates unique constraint "uq_wiki_pages_type_slug"`로 실패했다.

### 조치 (Flyway 도입으로 해결)

수동 DDL + 팀원 개별 공지 대신, **Flyway 마이그레이션으로 자동 해결**하도록 전환했다.

- 잔재 제거 마이그레이션: `backend/src/main/resources/db/migration/V2__drop_leftover_wiki_pages_unique.sql`
  - 내용: `ALTER TABLE wiki_pages DROP CONSTRAINT IF EXISTS uq_wiki_pages_type_slug;`
  - 잔재가 없는 DB(리셋/신규)에서는 `IF EXISTS`로 no-op, 잔재가 남은 DB(운영/미리셋 팀원)에서는 제거된다.
- baseline 스키마: `backend/src/main/resources/db/migration/V1__baseline_schema.sql` (엔티티 16개 기준 깨끗한 스키마. 잔재 constraint 없음)
- 팀원은 `./gradlew bootRun`만 하면 자동 적용된다. 별도 수동 DDL·공지가 필요 없다.

### 검증

- 빈 DB 기동 시 Flyway가 V1 → V2를 적용하고 `ddl-auto=validate`가 통과했다. `flyway_schema_history`에 2건 success 확인.
- 적용 후 `wiki_pages`에는 `uq_wiki_pages_workspace_type_slug`만 남고 `uq_wiki_pages_type_slug`는 없음을 확인했다.
- `./gradlew test --rerun-tasks` (Testcontainers) 통과. Test worker 로그에 `Successfully applied 2 migrations` 확인.

## 부수 작업: Flyway 마이그레이션 도구 도입

위 잔재 문제의 근본 원인인 `ddl-auto=update`(컬럼/제약 삭제·변경 미반영)를 벗어나기 위해, 스키마를 Flyway로 버전 관리하도록 전환했다.

- `ddl-auto`를 `update` → `validate`로 변경. 스키마의 단일 소스는 Flyway.
- `backend/build.gradle`에 `flyway-core`, `flyway-database-postgresql` 추가.
- `application.properties`에 `spring.flyway.enabled/baseline-on-migrate/baseline-version` 추가.
- 팀원 사용법(최초 1회 리셋 / 평상시 pull+bootRun / 스키마 변경 시 Vn 작성 규칙): `backend/README.md`의 "데이터베이스 스키마 (Flyway)" 섹션.

### 관련 위치

- baseline 마이그레이션: `backend/src/main/resources/db/migration/V1__baseline_schema.sql`
- 잔재 제거 마이그레이션: `backend/src/main/resources/db/migration/V2__drop_leftover_wiki_pages_unique.sql`
- Flyway 설정: `backend/src/main/resources/application.properties` (`spring.flyway.*`, `spring.jpa.hibernate.ddl-auto=validate`)
- 의존성: `backend/build.gradle` (`org.flywaydb:flyway-core`, `org.flywaydb:flyway-database-postgresql`)
- 팀원 사용법: `backend/README.md` — "데이터베이스 스키마 (Flyway)"
