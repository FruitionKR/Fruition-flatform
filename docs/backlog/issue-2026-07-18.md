# 2026-07-18 이슈

## Wiki ingest evaluator 결과의 선택적 반영

### 문제

Wiki ingest evaluator가 concept 또는 evidence 문제를 찾아도 재시도 시 모든 semantic packet을 다시 생성해, 문제가 없던 의미 노트까지 달라질 수 있었다. 최대 재시도 후에도 issue가 남았는지 manifest에서 한눈에 확인할 상태값도 없었다.

### 반영

- observation의 명확한 오류는 raw semantic note에 deterministic repair를 적용하고 다시 normalize한 후 재평가한다.
- concept, evidence, source block target은 정규화 결과의 source block anchor로 해석한다.
- target block과 앞뒤 block, 기존 target 항목, evaluator feedback만 LLM에 전달해 `replace/remove/add` patch를 생성한다.
- patch는 evaluator가 지정한 path와 전달된 source anchor만 수정할 수 있으며, 무관한 semantic note와 항목은 유지한다.
- patch 적용 후 전체 note를 다시 정규화하고 evaluator를 실행한다.
- patch 호출이나 검증에 실패하면 관련 packet 재생성, target을 해석할 수 없으면 전체 packet 재생성으로 fallback한다.
- 평가 기록에 `retry_mode`와 성공한 `applied_patch_operations`를 남긴다.
- 실제 문서에 없는 source block target은 선택 재생성으로 오기록하지 않고 전체 재생성으로 처리한다.
- `save_debug_json=true`이면 확정된 retry 방식과 patch operation을 `attempt_NN.retry.json`에도 남긴다.
- 최대 시도 후 actionable issue가 남으면 `generation_evaluation_status=unresolved`로 기록한다.
- 기존 page 생성, API 응답, DB 저장 흐름은 중단하지 않는다.
