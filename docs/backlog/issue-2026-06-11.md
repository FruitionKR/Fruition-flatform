## 백엔드 해결 이슈

### 1. 문서 상세 API의 Wiki page 연결 조회 누락

- 대상: `GET /api/documents/{document_id}`
- 현상: 응답의 `wiki_pages`가 아직 빈 배열이다.
- 원인: `document_wiki_links`와 `wiki_pages` 데이터는 생성되지만 `DocumentService.findById()`에서 아직 연결 조회를 하지 않는다.
- 해결 방향:
  - `DocumentService.findById()`에서 문서 ID 기준으로 `document_wiki_links`를 조회한다.
  - 연결된 `wiki_pages`를 함께 조회해 API 계약의 `wiki_pages` 응답 형식으로 매핑한다.
  - `relation_type`, `confidence`가 응답에 포함되는지 확인한다.

### 2. Gradle 테스트의 TestcontainersConfiguration 참조 실패

- 대상 명령: `./gradlew test`
- 현상: 기존 테스트 파일의 `TestcontainersConfiguration` 참조 문제로 테스트가 실패한다.
- 대상 파일:
  - `backend/src/test/java/fruition/poc/BackendApplicationTests.java`
  - `backend/src/test/java/fruition/poc/TestBackendApplication.java`
- 해결 방향:
  - 현재 테스트 구성에서 `TestcontainersConfiguration`이 필요한지 재검토한다.
  - 필요하면 누락된 테스트 설정 클래스를 복구하거나, 사용하지 않는 참조를 제거한다.
  - 로컬 통합 환경 기준으로 테스트가 안정적으로 실행되는지 확인한다.

### 3. 문서와 Wiki page 이름 변경 API 필요

## AI / Pipeline 해결 이슈

### 1. LLM 결과 Markdown 저장 경로가 pipeline 컨테이너 내부 경로에 의존

- 현상: LLM 결과 Markdown의 `markdown_uri`가 현재 pipeline 컨테이너의 `/app/runs` volume 경로로 저장된다.
- 문제: Spring API가 컨테이너 내부 경로에 의존하게 되어 실행 환경이 바뀌면 Markdown 조회가 불안정해질 수 있다.
- 해결 방향:
  - Wiki Markdown을 MinIO의 `wiki/` prefix에 저장하도록 변경한다.
  - `markdown_uri`는 Spring API가 접근 가능한 Object Storage URI로 저장한다.
  - source page와 concept page 모두 동일한 저장 규칙을 적용한다.

### 2. 실패 검증 과정에서 남은 로컬 DB 처리 상태 데이터 정리 필요

- 현상: 이전 실패 검증 과정에서 생성된 `processing` 또는 `failed` 상태 문서가 로컬 DB에 남아 있다.
- 문제: 데모나 통합 테스트 시 오래된 실패 데이터가 현재 상태 확인을 방해할 수 있다.
- 해결 방향:
  - 개발 DB 초기화 절차를 정리한다.
  - 테스트 데이터 정리 스크립트 또는 운영 절차를 마련한다.
  - 데모 전 clean 상태 복구 절차에 포함한다.
