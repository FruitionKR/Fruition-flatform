# 2026-06-21 이슈

## 완료: llmPipeline 원본 block 기준 query evidence 계약 변경

### 배경

query 답변의 `[n]` 인용은 Wiki page 내부 문장 위치가 아니라 원본 문서 block을 가리켜야 한다.
이전 `evidence_snippets`는 `page_id`, `page_type`, `page_title`, `page_url`, `paragraph_index`, `sentence_index`처럼 Wiki page 기준 필드를 반환해 원본 문서 하이라이트에 바로 사용할 수 없었다.

### 이번 브랜치에서 처리한 llmPipeline 범위

- `source_blocks` 테이블 추가: `(document_id, block_id, text)` 최소 구조.
- `run_lab.py`가 `source_blocks.json`을 항상 생성하고 manifest에 경로를 포함하도록 변경.
- pipeline run persist 단계에서 `source_blocks.json`을 읽어 `source_blocks` 테이블에 저장.
- query `evidence_snippets` 응답을 원본 block 기준으로 변경.
- block citation(`[B0005]` 등)이 없는 Wiki 문장은 evidence 후보에서 제외.
- source page의 `Categories`, `Core Concepts`, `Section Candidates`, `Mentions` 섹션을 별도 retrieval representation으로 점수 계산에 반영.

### 새 pipeline evidence 계약

```json
{
  "rank": 1,
  "source_document_id": "doc_1f9a74af",
  "source_block_ids": ["B0005", "B0006"],
  "text": "원본 block citation이 붙어 있던 근거 문장"
}
```

| 필드 | 의미 |
|---|---|
| `rank` | 답변 본문 `[1]`, `[2]` citation과 매칭되는 근거 순번 |
| `source_document_id` | 원본 문서 id |
| `source_block_ids` | 원본 문서를 block 단위로 나눈 id 목록 |
| `text` | DB quote 저장 및 UI preview에 사용할 근거 문장 |

제거된 필드:

- `page_id`
- `page_type`
- `page_title`
- `page_slug`
- `page_url`
- `page_role`
- `score`
- `paragraph_index`
- `sentence_index`

### Spring 후속 작업

- `PipelineQueryResponse.EvidenceSnippet`를 새 계약에 맞춰 변경한다.
  - 추가/유지: `rank`, `source_document_id`, `source_block_ids`, `text`
  - 제거: Wiki page 기준 필드와 `score`, `paragraph_index`, `sentence_index`
- `QueryResponse`는 pipeline 응답의 `evidence_snippets`를 그대로 전달한다.
- `chat_message_references` 저장 구조는 원본 기준으로 바꿔야 한다.
  - 최소 컬럼 후보: `rank`, `document_id`, `source_block_ids` 또는 별도 join table, `quote`
  - 기존 `wiki_page_id`, `page_role`, `paragraph_index`, `sentence_index` 기반 저장 로직은 더 이상 맞지 않는다.
- block 조회 API를 추가한다.
  - `GET /api/documents/{documentId}/blocks`
  - 응답 최소 필드: `block_id`, `text`

### Frontend 후속 작업

- Markdown 답변 렌더링에서 `[n]` citation을 클릭 가능 요소로 렌더한다.
- 클릭한 rank와 같은 `evidence_snippets[].rank`를 찾아 `source_document_id`와 `source_block_ids`를 얻는다.
- `GET /api/documents/{documentId}/blocks`로 원본 block 목록을 가져온다.
- `source_block_ids`에 해당하는 block 전체를 하이라이트하고 스크롤한다.
- 1차 범위는 markdown/text 원본 또는 추출 텍스트 뷰로 한정한다. PDF iframe 위 좌표 하이라이트는 별도 문제로 분리한다.

### 검증 기준

- pipeline `/query` 응답의 `evidence_snippets`에 Wiki page 기준 필드가 없다.
- block citation이 없는 summary/정의 문장은 evidence 후보가 되지 않는다.
- block citation이 있는 문장만 `source_document_id` + `source_block_ids`와 함께 반환된다.
- source page의 category/core/section/mention 문구가 query retrieval 점수에 반영된다.
